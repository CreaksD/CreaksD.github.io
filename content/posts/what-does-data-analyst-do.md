很多人会把「数据分析师」和「大数据开发」混在一起，其实两者是两条完全不同的技能树。先看数据分析师的核心技能：

```

│
├── 1. Excel
│      ├── 函数
│      ├── 透视表
│      └── 图表

├── 2. SQL ⭐⭐⭐⭐⭐
│      ├── 查询
│      ├── JOIN
│      ├── 聚合
│      ├── 窗口函数
│      └── CTE
│
├── 3. Python ⭐⭐⭐
│      ├── Pandas
│      ├── NumPy
│      └── Matplotlib

├── 4. 统计学 ⭐⭐⭐⭐
```

## 注意：别把大数据技术混进来

而 Kafka、Flink、Spark、HDFS、Iceberg、Hudi、Lakehouse、StarRocks、数据治理、数据湖、数据仓库这些，其实更多属于**数据工程 / 大数据开发 / 数据平台**的范畴——它们是「存数据和算数据的基础设施」，不是分析师日常用的工具。

## 三类工作的本质区别

| 角色 | 回答的问题 | 核心工作 |
|------|-----------|---------|
| Java 开发 | 这个业务功能怎么实现？ | 写代码实现功能 |
| 大数据开发 | 这么多数据怎么稳定地存、算、管、用？ | 搭管道、建数仓、调引擎 |
| 数据分析师 | 这些数据到底说明了什么？我们应该做什么？ | 取数、分析、出结论、推动决策 |

一句话：**分析师离业务更近，开发离基础设施更近**。想入行数据分析，先把 SQL 和业务分析吃透，再补统计学和 BI；想做大数据的，则要往分布式计算和数据平台方向走。
